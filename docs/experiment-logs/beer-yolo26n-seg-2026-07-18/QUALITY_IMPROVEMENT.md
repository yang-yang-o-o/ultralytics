# 分割观感提质：原理、对策与学习笔记

> 背景：YOLO26n-seg @ beer，`imgsz=640`，30 epoch 后 Mask/Box mAP50-95 ≈ **0.995**，但肉眼看边缘仍偏糙。  
> 核心判断：**不是“没学会”**，而是 **有效分辨率 + 模型容量 + mask 监督粒度** 共同构成的上限问题。  
> 对应会话：`SESSION.md` §5.5；基线配置见 `examples/beer_seg_train.py`。

---

## 0. 先分清两件事：指标好 vs 看起来好

| 维度 | 当前情况 | 含义 |
|------|----------|------|
| COCO 风格 Mask mAP | ~0.995（val 30 张几乎满分） | 实例定位与粗略掩膜覆盖已经很好 |
| 视觉边界（锯齿、毛边、贴合瓶口/瓶底） | 用户觉得糙 | 对 **高频边缘** 敏感，mAP 不敏感 |

**学习点：**

- Mask mAP（尤其 mAP50）对 **粗糙但仍大体重合** 的 mask 很宽容。  
- 观感更接近 **边界对齐误差**（boundary IoU / Trimap / Boundary F1），应用落地时往往更该看这些。  
- 因此：**提质实验要以“边缘指标 + 可视化难例”为主，不能只看 mAP 是否再涨 0.001。**

本数据集抽查：多边形标注相对原 `mask/*.png` 的 IoU ≈ **0.993–0.994** → **标注不是主瓶颈**；瓶颈在训练/推理管线对细节的保留能力。

---

## 1. 提高有效分辨率（性价比通常最高）

### 现象与原因

- 原图约 **1292×964**。  
- 训练/默认推理用 **`imgsz=640`**：最短边或方形 letterbox 到 640 后，细节（瓶口、商标边、遮挡轮廓）被下采样抹掉。  
- 网络只能在 **已损失细节的特征图** 上回归 mask，后期再怎么训也补不回高频信息。

### 做法

1. **训练与验证**改为 `imgsz=960` 或 `1280`  
   - 基线 `imgsz=640, batch=16` 时显存约 **3.4GB** 量级 → 3080 Ti 12GB 有空间上探。  
   - 分辨率升高后 batch 可能需降到 8，以显存为准。  
2. **推理**打开 `retina_masks=True`  
   - Ultralytics 默认 `retina_masks=False`：mask 在较低分辨率上处理后上采样，边界易糊。  
   - `retina_masks=True`：在更高分辨率上生成/裁剪 mask，**观感提升常立刻可见**，且可不改权重先试。

### 学习点

- 分割任务对输入分辨率的依赖通常 **强于** 纯检测。  
- **先提高 imgsz / retina_masks，再换大模型**，往往更省算力。  
- 训练 imgsz 与部署 imgsz 尽量一致；只训 640 却推 1280，收益有限甚至分布偏移。

### 建议实验

| 实验 | 配置 | 目的 |
|------|------|------|
| A0 | 现权重 + `predict(..., retina_masks=True)` | 零成本看推理侧观感 |
| A1 | 重训 `imgsz=960, batch=8~16` | 训练侧保留细节 |
| A2 | 重训 `imgsz=1280, batch=4~8` | 逼近原图分辨率 |

## 2. 换更大模型（边界比盲目加 epoch 更有效）

### 现象与原因

- `yolo26n-seg` 是 **nano**：参数/宽度最小，对细轮廓的表达能力弱。  
- 在数据已“简单、单类、高对比 mask”时，n 模型容易 **检得准但切得糙**。  
- 继续把 epoch 从 30 拉到 100，对 n 模型边缘的提升往往 **小于** 换成 s/m。

### 做法

按容量递增试：

1. `yolo26s-seg`  
2. `yolo26m-seg`（再不够再考虑 l/x）

### 学习点

- **容量不够时，加数据增强或加 epoch 无法替代表达力。**  
- 单类、场景相对单一的工业/实验室物体，s 往往是速度与边缘质量的甜点；m 用于更咬边缘。  
- 换模型后应用 **同一 imgsz / 同一评估协议** 对比，否则结论混淆。

### 建议实验

| 实验 | 模型 | 备注 |
|------|------|------|
| B1 | yolo26s-seg + imgsz=960 | 推荐下一跳基线 |
| B2 | yolo26m-seg + imgsz=960 | 若 s 仍不够细 |

## 3. 加细 mask 训练监督（`mask_ratio`）

### 现象与原因

- Ultralytics 默认 **`mask_ratio=4`**：GT mask 在 loss 计算前按比例下采样。  
- 好处：省显存、加速。  
- 代价：**边缘监督信号变钝**，模型倾向学“填对区域”而非“贴准边界”。

### 做法

- 试 `mask_ratio=2`，仍不够再试 `1`。  
- 显存上涨时配合 **`batch=8`**（或更小）。  
- 相关默认还有 `overlap_mask=True`（多实例合并到一张 mask 上训）；beer 多为单实例，影响较小，但多瓶同框时需留意。

### 学习点

- 分割 loss 的 **空间分辨率** 和输入 `imgsz` 是两件不同的事：  
  - `imgsz` 决定骨干看到的细节；  
  - `mask_ratio` 决定 **监督 mask 有多糊**。  
- 两者都大（高 imgsz + 低 mask_ratio）才对边缘最友好，但也最吃显存。

### 建议实验

| 实验 | 配置 |
|------|------|
| C1 | `mask_ratio=2, batch=8, imgsz=960` |
| C2 | `mask_ratio=1, batch=4~8`（显存允许时） |

## 4. 训练策略微调（后期精细化）

### 推荐调整（相对当前 30 epoch 默认增广）

| 参数 | 当前/默认倾向 | 建议 | 理由 |
|------|----------------|------|------|
| `epochs` | 30 | **80–150** | 给后期 close_mosaic 阶段足够精细拟合 |
| `close_mosaic` | 默认 10 | **15–20** | 最后阶段关 mosaic，利于边界收敛 |
| `mosaic` | 1.0 | **0.5** | beer 姿态已多样，过强拼接伤边缘一致性 |
| `scale` | 0.5 | **0.3** | 减轻极端缩放导致的轮廓形变 |
| `degrees` | 0 | **保持 0** | 无需额外大旋转（视数据而定） |
| `box` | 7.5 | 保持 | 框仍要准，框漂会拖累 mask crop |
| `cls` | 0.5 | 可略降 | 单类任务分类压力小，相对更关注定位/分割 |

### 学习点

- Mosaic 对检测/分割早期泛化有益，但对 **精细轮廓** 后期常有害 → 所以有 `close_mosaic`。  
- 几何增广过强 ≈ 人为制造标注与外观不对齐的“伪噪声边缘”。  
- 单类数据不要把优化重点放在 cls；框与 mask 的对齐更重要。

### Loss 权重直觉

- `box`：框不准 → mask 头在错误 ROI 上学习。  
- seg loss：直接管填充与边缘；在 Ultralytics 中随 task 启用，可通过相关超参/增益调节关注度（具体键名以当前版 `default.yaml` / trainer 为准）。  
- 实操：**先改分辨率与模型，再微调 loss 权重**，避免过早调参。

## 5. 标注侧再挤一点（次要但便宜）

### 现状

- `approxPolyDP(epsilon = 0.001 * perimeter)`  
- 相对二值 mask IoU ≈ 0.994，点数约几十～上百  

### 可做

- 将 epsilon 降到 **`0.0005`**（或更小），轮廓点更密，减少多边形折线对圆滑瓶身的逼近误差。  
- 或提高保留点数上限后再训一轮做 **A/B**。  

### 学习点

- 多边形是 mask 的有损压缩；IoU 0.994 已经很好，**继续加密的收益通常小于提高 imgsz**。  
- 仍建议做一次对照：排除“标注折线”被误认为“模型糊”。  
- 理想情况：评估时直接与 **原 PNG mask** 比，而不仅与多边形标签比。

## 6. 评估方式对齐“观感”

### 不要只看

- `metrics/mAP50(M)`、`mAP50-95(M)`（当前已接近饱和，区分度差）

### 建议增加

1. **与 `mask/*.png` 的 mean IoU**（全图或实例 crop）  
2. **Boundary F1 / 边界带 IoU**（只在轮廓附近几像素评估）  
3. **难例集可视化**：遮挡、截断、远处小目标、强反光、运动模糊  
4. 固定随机种子与同一 `conf`/`iou` 阈值，保证对比公平  

### 学习点

- 指标饱和时，**观感实验要用更“刁钻”的度量**，否则无法判断提质是否成功。  
- val 仅 30 张，mAP 方差小、易满分；应用结论应结合难例目视 + 边界指标。

## 7. 针对 beer 的性价比排序（执行顺序）

按预期 **观感收益 / 实现成本**：

1. **更大 `imgsz` + 推理 `retina_masks=True`**  
2. **换 `yolo26s-seg` / `yolo26m-seg`**  
3. **`mask_ratio=2`（再考虑 1）**  
4. **加长训练 + 减弱 mosaic/scale + 更大 `close_mosaic`**  
5. **加密多边形标注**  
6. 全程用 **mask IoU / boundary F1 + 难例可视化** 验收，而不是只看 mAP

## 8. 概念速查（便于复习）

| 术语 | 一句话 |
|------|--------|
| `imgsz` | 送入网络的图像边长；分割细节的上限之一 |
| `retina_masks` | 推理时是否以更高分辨率生成 mask |
| `mask_ratio` | 训练时 GT mask 下采样倍数；越大监督越糊、越省显存 |
| `close_mosaic` | 最后 N 个 epoch 关闭 mosaic，利于精细收敛 |
| Mask mAP | 区域重合导向的检测式分割指标；对毛边不敏感 |
| Boundary F1 | 轮廓邻域精度；更接近人眼“切得齐不齐” |
| nano/s/m | 模型宽度/深度档位；边缘质量常随档位上升 |
